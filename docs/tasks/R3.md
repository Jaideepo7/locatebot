## What to build
1. **Pi side — `locatebot/remote/robot_zmq.py`: `ZmqRobotLink`** implementing `RobotLink`: `send(dict)` turns `MISSION_REQUEST` / `MISSION_CANCEL` dicts into `MissionRequest` / `MissionCancel` messages on the **Pi's PUB socket (5555)**; a thread subscribes to the Orin (5556) for `mission_status` and `orin_status`, converting statuses back into the frames `MissionService.on_robot_frame` expects; `connected` = an `orin_status` heard within 3 s (calls `on_robot_connected/disconnected` on changes). The Pi process already owns the 5555 PUB socket in the full car (T1.3): accept an injected `Publisher` so both share one socket; standalone mode creates its own. Add `--robot zmq --orin-host <addr>` to `tools/remote_run.py`.
2. **Orin side — `locatebot/orin/missions.py`: `MissionBridge(runtime, publish, clock)`**, fed `MissionRequest`/`MissionCancel` from the Orin's subscriber (extend `pi_source` in `tools/orin_run.py` to subscribe `mission_request`, `mission_cancel`; publish `MissionStatus` via `PiDriveSink`'s publisher).
   - Validation (port from `JetsonAgent`): reject expired / future-dated beyond 5 s skew / duplicate id / a second concurrent mission → `MissionStatus(state=FAILED or CANCELLED per protocol, reason=...)` or an explicit reject as the protocol defines.
   - Start: `runtime.set_goal(f"find {target}")`; with an LLM brain → let it act (approve or auto mode as configured); **without** a brain (`--llm none`) → run the routine `search([target])` then on success `go_to(item=target)` via `runtime.submit_operator`.
   - Status mapping (only what really happened; send each state once, in allowed transition order): ACCEPTED when started; SEARCHING when a `search`/`explore`/`look_around` is running; TARGET_DETECTED when the target's track becomes **confirmed** (message includes map position); APPROACHING when `go_to(item=target)` runs; COMPLETED when that `go_to` succeeds; FAILED with reason `NOT_FOUND` (search ended, target missing), `NO_PATH`, `TIMEOUT` (mission TTL), `ROBOT_FAULT` (executor internal error); CANCELLED after a cancel once the executor has stopped. Target lost during APPROACHING → back to SEARCHING (allowed transition).
   - Cancel → `runtime.submit_operator(STOP)`, clear goal, report CANCELLED. Link to the Pi lost (no Pi scans for 2 s) → STOP and keep the mission state; on reconnect re-report the current state (the Pi's own safety stop already stops the car).
   - `tick(now)` called from the Orin control loop (wire it into `OrinApp`/`OrinRuntime.step`); thread-safe; never blocks the control step.
   - Matching the target name to item tracks: case-insensitive exact match on the normalised description (the same text vision searches for); document that wording matters (`docs/vision/README.md`: short nouns).
3. **Docs:** `docs/remote/README.md` (mission flow diagram, state mapping table, failure reasons), `docs/orin/README.md` (mission bridge section).

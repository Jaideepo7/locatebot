# M1 — Reuse a saved map: localize the car inside an existing `.lbmap`

You are one agent on the `locatebot` project: an RC car that maps rooms with an RPLIDAR C1 (2D, ~10 scans/s, ~508 points/scan, ~370 valid in a cluttered room, range noise ~0.6 mm) into an occupancy grid saved as `.lbmap`. Today **every session starts a new map from scratch** at pose (0, 0, 0). The team wants a map that keeps improving across sessions until it is "semi-constant", so that later (M2/M3) anything that doesn't match it can be treated as new (people, moved objects). Step one, your task: **load a saved map and track the car's pose inside it**, while updating it slowly.

## What to build
1. **`locatebot/lidar/localize.py`: `MapLocalizer(grid, config)`**
   - Builds a `LikelihoodField` once from the saved map's OCCUPIED cell centres (rebuild lazily when the map changes beyond a threshold).
   - `initialize(scan, guess: Pose2D | None, search_xy_m, search_theta_rad) -> LocalizeResult`: global-ish search around the guess (dock pose or operator click); with `guess=None` do a coarse grid over the map's FREE area + 12–24 headings and pick the best converged, distinct-from-runner-up solution (report ambiguity instead of guessing when the top two scores are close).
   - `update(scan) -> LocalizeResult`: track against the map with motion prediction (like `ScanOdometry`), small search window; `LocalizeResult(pose, score, converged, ambiguous, lost)`; declare **lost** after N consecutive non-converged updates or a score below a floor, and expose it (never silently drift).
   - Optional blend: if matching against the map is weak (mostly new obstacles), fall back to scan-to-scan odometry for a few updates and say so.
2. **Slow map updating ("semi-constant"):** `integrate_slow(grid, scan, pose, rate)`: same ray model as `OccupancyGrid.integrate` but scaled increments (e.g. 0.2×) for cells that are already confident, full increments for unknown cells; only integrate when the pose is converged and not ambiguous. Write it without changing `OccupancyGrid`'s existing behaviour (add a method/function; `grid.py` is lane code, not a frozen contract, but keep existing callers bit-identical).
3. **`LiveMapper` mode:** `LiveMapper.from_saved(path, guess=None)` loads the map and uses `MapLocalizer` instead of fresh odometry; `home` = the saved map's origin pose metadata (or the guess); `stats()` gains `mode` (`mapping`/`localizing`), `lost`, `ambiguous`, `last_score`; `save()` writes the updated map (same file name + `.v2` or overwrite with `--save-map`).
4. **CLI:** `tools/orin_run.py --map maps/<name>.lbmap [--start-pose x,y,deg]` uses it; the operator page shows "localizing / lost" in the status table.
5. **Tool:** `tools/relocalize.py --map <lbmap> --log <lbscan> [--guess x,y,deg]`: replays a recording against a saved map and prints pose track, scores, lost/ambiguous events — for the team to check on real data.
6. **Docs:** `docs/lidar/README.md` (localization section: method, parameters, failure modes, how to recover), `docs/orin/README.md` (`--map`).

## Tests (`tests/lidar/test_localize.py`, synthetic)
- Build a map in `demo_room()` from `demo_trajectory()`; restart at a pose offset by (0.5 m, -0.3 m, 25°) with a guess within the search window → converges within 0.1 m / 3° in ≤ 5 scans, then tracks a new trajectory with error < 0.1 m.
- No guess: global init finds the right pose in an asymmetric room; in a symmetric room (`Room.box(6, 6)`) reports `ambiguous` instead of a confident wrong answer.
- Moved furniture (add a box not in the map) → still converged; the new box's cells start changing slowly, the old map isn't wiped.
- Lost detection: teleport the sim car → `lost` within N updates; never a silent jump.
- Slow update keeps existing callers identical (golden test on `OccupancyGrid.integrate`).
- Runtime: `LiveMapper.from_saved` thread-safety like `tests/orin/test_live_map.py`.
- Performance: one `update` < 30 ms on the laptop for 508-point scans (note: the Orin is ~3× slower; report both if you can run on the Orin: `ssh melvin@192.168.8.140`, repo `~/locatebot`, tests via `.venv/bin/python -m pytest`; use `pkill -f "[p]attern"` style if you kill anything there).

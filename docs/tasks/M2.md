## What to build
1. **Layers — `locatebot/lidar/layers.py`: `LayeredMap`**
   - `static`: the M1 slowly-updated `OccupancyGrid` (the room).
   - `dynamic`: a short-lived grid (decays toward unknown with a half-life of ~2–5 s) holding points classified as new/moving.
   - `extra`: named float32 layers registered by other modules (M3 adds `glass_or_low`, `wifi_rssi`), each with its own update rule and metadata.
2. **Change detection per scan (`classify_points`)** with the localized pose: for every valid beam endpoint, look up the static layer; a hit in a cell the static map is **confidently FREE** (and whose ray from the sensor also crossed confidently free cells) is **new**; a hit on a static OCCUPIED cell is **room**; elsewhere **unknown**. Cluster the new points with `cluster_scan` logic (in the map frame) → `ChangeBlob(centroid_xy, width_m, n_points, first_seen_s, last_seen_s, persistence)`.
3. **Update rules:** new points go **only** into `dynamic` (never into `static`); `static` keeps M1's slow updates but **skips rays whose endpoint was classified new** (so a person standing in a doorway doesn't erase the free space behind them or add a wall); a blob that stays still for > `promote_after_s` (e.g. 120 s, configurable) is promoted into `static` as a slow update (a moved chair becomes part of the room); a static obstacle seen as free for long enough fades (existing slow update).
4. **Planning uses both:** `build_costmap` (nav) must treat dynamic occupied cells as obstacles too: expose `LayeredMap.planning_grid()` returning an `OccupancyGrid` combining static + dynamic (max of occupancy), and use it in `LiveMapper.grid_snapshot()` when layered mode is on. Don't change `locatebot/nav/` APIs.
5. **`.lbmap` v2 (`LBMAP2`)** in `locatebot/lidar/mapfile.py`: same header idea plus a layer table (name, dtype, scale/offset, update params) and per-layer blobs, one CRC over everything, atomic write; `load_map` reads **v1 and v2** (v1 → static layer only); `save_map` keeps writing v1 unless layers are passed (backward compatible); PGM/YAML export still shows the static layer. Document the layout at the top of the file as `LBMAP1` is.
6. **World state hook:** `locatebot/orin/world.py` gets `changes: list[ChangeBlob]` input and the LLM summary line `changes: 2 new things: 0.4 m wide at 1.2 m ahead (moving), ...` via a new optional parameter (don't break existing calls). (People classification is M3.)
7. **Docs:** `docs/lidar/README.md` (layers, change detection, promotion/decay, v2 format), `docs/orin/README.md`.

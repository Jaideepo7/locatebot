# R1 — Port the Photon/Telegram messaging core to `locatebot/remote/` (runs on the Raspberry Pi)

You are one agent on the `locatebot` project: an RC car (Raspberry Pi 4 for motors/safety/sensors, Jetson Orin for vision/mapping/LLM). Customers will send `/find <item>` to a Telegram bot through **Photon** (a cloud messaging service, https://photon.codes); the robot searches and replies. A teammate built this on branch `origin/feat/photon-dispatch` (author chanabyte, 4 commits, ~4,700 lines) before the current Pi/Orin runtime existed. The review (`docs/ROADMAP.md`, section R) decided: **keep its messaging half, move it to the Pi, drop FastAPI, and replace its Jetson WebSocket robot link with an interface** (a ZeroMQ adapter comes in R3). Your job is the port.

## Key facts about the branch (verified 2026-11-08)
- It merges onto `main` with only a `.gitignore` conflict; all its 327 tests pass (with FastAPI installed).
- `MissionService(store, link, robot_id, clock)` talks to the robot **only** through `link.send(msg: dict) -> bool` plus callbacks `on_robot_frame(frame)`, `on_robot_connected()`, `on_robot_disconnected()`, and `tick()` for timeouts. That is the seam to keep.
- Decision logic is stdlib; FastAPI/uvicorn/httpx (`backend` extra) and `websockets` (`robot-link` extra) are only adapters.

## What to build
1. **Bring the code over with history.** `git checkout origin/feat/photon-dispatch -- <paths>` then `git mv` into the new layout; say in the commit message that the code originates from chanabyte's commits `97dd665`, `5941277`, `137536a`.
2. **New layout `locatebot/remote/`:**
   - `photon.py` (from `backend/messaging/photon.py`: Standard Webhooks verification, `message.received` parsing, `PhotonClient.send_text`), `messaging.py` (from `messaging/base.py`), `commands.py`, `notifier.py` (texts + `OutboxSender`), `store.py` (SQLite: event dedupe, missions, outbox in one transaction), `missions.py` (`MissionService`), `config.py` (`Settings.from_env`, secrets never in errors/repr), `protocol.py` (from `dispatch/protocol.py`: `MissionState`, transitions, `normalize_description`, limits).
   - `robot.py`: a `RobotLink` **Protocol** (`send(msg: dict) -> bool`, `connected` property) and a `FakeRobotLink` for tests (scriptable like the branch's `ScriptedSink`: plays statuses on a timer, can drop/reconnect). Remove the WebSocket authentication code (the Pi talks to the Orin over our private Ethernet link; R3 adds `ZmqRobotLink`).
   - `server.py`: stdlib `ThreadingHTTPServer` replacing `backend/app.py`: `POST /api/photon/webhook` (keep: signature check, 204/400/503 policy), `POST /api/missions`, `GET /api/missions/{id}`, `POST /api/missions/{id}/cancel` (operator bearer token, constant-time compare), `GET /healthz`. No FastAPI, no uvicorn.
   - `service.py`: `RemoteService` wiring store + provider + `MissionService` + `OutboxSender` + one background thread running `tick()`/`run_once()` every 0.5 s; `start()`/`stop()`.
3. **Delete what doesn't move:** `dispatch/ws_client.py`, the FastAPI app, `tools/fake_jetson.py` (replace with `tools/fake_remote_robot.py` using `FakeRobotLink` if useful). Do **not** add `locatebot/backend/` or `locatebot/dispatch/` to `main`.
4. **Config:** env vars as on the branch (`PHOTON_API_KEY`, `PHOTON_PROJECT_ID`, `PHOTON_WEBHOOK_SECRET`, `OPERATOR_API_TOKEN`, `PHOTON_MODE=console|live`, `DISPATCH_DB_PATH`, timeouts); drop `JETSON_DEVICE_ID`/`JETSON_AUTH_TOKEN`/`BACKEND_PUBLIC_URL` requirements (webhook mode becomes optional; R2 adds WebSocket mode). Keep `.env.example` (no real values) and make sure `.env` stays git-ignored.
5. **Docs:** `docs/remote/README.md`: what runs on the Pi, env vars, routes, behaviour rules (one active mission, the robot reports and the backend only fails on timeouts, outbox dedupe, ownership, rate limit), credit to the original branch, what R2/R3 add.

# R4 — Give the LLM a goal ("find the marker") and let the operator set it

You are one agent on the `locatebot` project: an RC car whose high-level "brain" is an LLM (the team uses **Nemotron through NVIDIA's API**) that picks from fixed skills (`explore`, `search`, `go_to`, `follow`, `look_around`, `stop`, `return_home`, plus `continue`). Today the LLM sees a world-state summary but **no goal**: it doesn't know what the operator (or a mission) wants. Your job: add the goal end to end.

**Prerequisite:** Step C merged: `WorldState.goal: str = ""` exists in `locatebot/mission/types.py`. If not, stop and report.

## What to build
1. **Runtime:** `OrinRuntime.set_goal(text: str, source: str = "operator")` and `clear_goal()`; validate (strip, collapse whitespace, 1–200 chars, no control characters); store with the time set; event `"goal set: ..."` / `"goal cleared"`; `_world_state` fills `WorldState.goal`. Thread-safe.
2. **Summary:** `render_world_state` prints `goal: <text>` as the **first line** when set (`goal: none` otherwise); keep the output bounded.
3. **Brain:** a goal change triggers a decision (`_trigger` reason `"new goal: ..."`); `DEFAULT_SYSTEM_PROMPT` gains rules: work towards the goal; choose items to search for from the goal using short common nouns; when the goal is achieved (e.g. arrived at the item), call `stop` with a reason saying it's done; if the goal is impossible (search failed), call `stop` and explain in the reason. Keep the existing rules and the `continue` guidance.
4. **Operator page + API:** `POST /goal {"text": "..."}` and `POST /goal/clear` on the Orin app (JSON-only, 400 on invalid); a goal text box + "Set goal" / "Clear" buttons on the mission page; the status JSON includes `goal`.
5. **Docs:** `docs/agent/README.md` (goal input and prompt rules), `docs/orin/README.md` (routes).

## Tests
- Summary: goal line first; `none` when empty; long goal truncated.
- Brain: setting a goal while idle triggers exactly one request whose prompt contains the goal; changing it mid-skill triggers a decision (the LLM may answer `continue`); clearing it doesn't trigger a spurious decision storm.
- Runtime/app: validation errors → 400; event recorded; status shows the goal; page has the controls and still no external URLs.
- **Simulation:** extend the scripted-LLM pattern of `tests/orin/test_e2e_sim.py` with a policy that reads only the `goal:` line (e.g. "find the bolt") to choose `search(["bolt"])`, then `go_to(bolt)`, then `stop`; assert it finishes near the bolt.

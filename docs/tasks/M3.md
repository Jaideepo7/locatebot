## What to build
1. **People tracker — `locatebot/lidar/people.py`: `PeopleTracker`**
   - Candidate detection from M2 change blobs: **leg pairs** (two blobs ~0.08–0.25 m wide, centres 0.1–0.5 m apart) or a single blob 0.25–0.6 m wide (person close, or LiDAR mounted higher). Document the geometry and make thresholds configurable (mount height changes them).
   - Tracking: constant-velocity Kalman (or α-β) filter per track in the map frame; gated nearest-neighbour association (Mahalanobis gate); track birth after 3 consistent detections, death after `max_missed_s`; speed estimate; `moving` flag above ~0.15 m/s.
   - Classification confidence: moving + leg-pair geometry → likely person; static blob → "object" (not a person) unless the camera confirms.
   - Camera confirmation: expose `wants_camera_check() -> PersonTrack | None` (a likely-person track without confirmation in the last 10 s); the runtime asks vision for `"person"` at low priority **only when no search is running** (vision is a shared, slow resource); a vision fix near the track sets `confirmed_by_camera`.
   - Output `PersonView` list into `WorldState.people` (via `build_world_state`), sorted by distance, capped at 5.
2. **Summary for the LLM:** `render_world_state` line `people: 1 person 1.2 m ahead walking left (0.6 m/s, camera-confirmed)`; `none` when empty. Keep it bounded.
3. **Ultrasonic layer `glass_or_low`:** Orin subscribes to `Range` (the Pi publishes them from T1.2). For each reading with the localized pose at its stamp: if the ultrasonic says something is at range r inside its ~15° cone **and** the LiDAR's beams in that cone see nothing nearer than r + 0.2 m, mark the cone's arc at r in the `glass_or_low` layer (low weight, slow decay, never cleared by LiDAR free-space rays). Planning treats confident `glass_or_low` cells as obstacles (through M2's `planning_grid`). Summary line: `glass or low obstacle: 0.6 m ahead (ultrasonic only)` when relevant.
4. **Wi-Fi coverage layer `wifi_rssi`:** on the Orin read the RSSI of the current Wi-Fi link (`/proc/net/wireless` or `iw dev <iface> link`; tool chosen at runtime, missing → layer disabled, never an error) at 1 Hz and write it into the layer at the current pose (running mean per cell); operator page shows it as an optional colour overlay; summary line only when the link is weak (< −75 dBm): `wifi: weak here (-80 dBm); strongest nearby at (x, y)`. This layer never affects planning or occupancy.
5. **Follow integration:** when `follow(item)` targets `person`/`people`, `SkillExecutor` uses the people tracker's track for the target (instead of raw clusters) between vision fixes.
6. **Docs:** `docs/lidar/README.md` (people tracking, glass layer, Wi-Fi layer, parameters, failure modes: chair legs, pets, sitting people, glass), `docs/orin/README.md`, `docs/agent/README.md` (new summary lines).

## Tests (synthetic)
- Sim room with a "person" = two small leg boxes walking a path (alternate leg offsets for gait) → one track, position error < 0.15 m, speed within 20 %; a static chair (four small legs in a square) → not a person; two people crossing → no identity swap in a simple crossing case (document limits otherwise).
- Track lifecycle: birth after 3 detections, death after `max_missed_s`; camera confirmation request only when no search runs; fake vision fix marks `confirmed_by_camera`.
- Ultrasonic layer: glass pane (no LiDAR return) + ultrasonic at 0.6 m → cells marked, planning blocked; LiDAR sees the same object → nothing added (not glass); readings never erased by LiDAR free rays; disabled cleanly without `Range` messages.
- Wi-Fi: parser tests for `/proc/net/wireless` and `iw` output samples; missing tool → disabled; layer saved/loaded in `.lbmap` v2.
- Summary/world: new lines appear, bounded, `none` when empty; follow(person) keeps within distance in the moving-person sim.
- Performance: tracker + layers < 10 ms per scan on the laptop.
